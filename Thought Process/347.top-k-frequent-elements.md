# 347. Top K Frequent Elements

## Thought process

1. Split into two separate sub-problems:
   1. Count how often each number appears.
   2. Out of those counts, find the k biggest.
2. Part 1 is a simple one-pass count (`Counter`/dict) — O(n).
3. Part 2 is the **exact same size-k min-heap trick as 215**, except comparing by *frequency* instead of raw value.
4. Push `(frequency, number)` tuples so the heap orders itself by frequency; whenever the heap exceeds size k, pop the weakest (lowest-frequency) entry.
5. Final answer: pull just the numbers back out of whatever's left in the heap.

## Why tuples with frequency first

Python compares tuples element by element. Putting `frequency` first means the heap sorts by frequency, while still carrying the original `number` along so you know which value each frequency belongs to for the final answer.

## Complexity

- Time: O(n log k)
- Space: O(n) for the count map + O(k) for the heap

## Common pitfall

Putting the tuple in the wrong order — `(number, frequency)` instead of `(frequency, number)` — which makes the heap compare by the raw number first instead of by frequency, silently producing the wrong "top k."

## Cold-review self-check

- Why does frequency have to come first in the tuple, not the number?
- What are the two sub-problems this splits into, and why does splitting it that way help?
- How is this the same heap trick as 215, just comparing a different field?
