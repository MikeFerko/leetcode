# 739. Daily Temperatures

## Thought process

1. Naive approach: for every day, scan forward until a warmer day shows up — O(n^2).
2. Key insight: don't re-scan from scratch each time. Keep a stack of days that are still "waiting" for a warmer day, and resolve several of them at once the moment a warmer day appears.
3. Store **indices**, not temperatures, on the stack — you need the position to compute `answer[i] = today - waiting_day` once it resolves.
4. For each day: while today's temperature beats the temperature at the index on top of the stack, pop that index and record how many days it waited (`today_index - popped_index`). One warm day can resolve many waiting days in a row.
5. Push today's index, move on.

## Why a monotonic stack

The stack only ever holds indices with strictly decreasing temperatures (hence "monotonic"). Every index is pushed exactly once and popped at most once, so even though there's a `while` loop nested inside the `for` loop, total work across the whole run is still O(n) amortized — not O(n^2).

## Complexity

- Time: O(n) amortized
- Space: O(n) worst case (strictly decreasing temperatures never get popped)

## Common pitfall

Pushing/comparing raw temperatures instead of indices. Without the index, you can't compute the day-gap for `answer[]` once a day resolves — the temperature value alone doesn't tell you *how far back* the waiting day was.
