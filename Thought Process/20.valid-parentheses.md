# 20. Valid Parentheses

## Thought process

1. Recognize the core requirement: brackets must close in the **reverse order** they were opened. That's a nesting rule, and nesting = LIFO = stack.
2. Build a map of closing bracket -> its required opener (`{")": "(", "]": "[", "}": "{"}`), so each check is O(1).
3. Walk the string once:
   - Opener -> push it.
   - Closer -> pop the stack and check it matches this closer's required opener. If the stack is empty, or the popped value doesn't match, the string is invalid immediately.
4. After the loop, the string is only valid if the stack is completely **empty** — every opener found a closer.

## Why a stack (not a queue)

A queue would match closers against the *oldest* unclosed opener (FIFO). But nesting requires matching the *most recently* unclosed opener (LIFO) — e.g. `([)]` is invalid because `)` must match the most recent opener (`[`), not the first one (`(`). Only a stack gives you that.

## Complexity

- Time: O(n)
- Space: O(n) worst case (a string of all openers)

## Common pitfall

Forgetting the final "stack must be empty" check — a string of unclosed openers like `"((("` never fails inside the loop (nothing invalid ever happens), so without checking `not stack` at the end, it would incorrectly return valid.

## Cold-review self-check

- What structure do you reach for when something must close in the reverse order it opened?
- What are the two distinct ways a closing bracket can fail the check?
- What's the one check people forget after the loop ends, and why does skipping it break the solution?
